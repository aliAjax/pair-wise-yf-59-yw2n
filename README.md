# 帆船赛现场控制和申诉处理

源提示词摘要：竞赛官维护组别、航线、起航时间和处罚记录，计时员提交到达数据，裁判处理抗议、重赛、弃权和成绩更正；冲突或重复处罚进入复核，操作保留时间线。

## 技术栈

React 19、TypeScript、Vite、Ant Design、Redux Toolkit、RTK Query、React Router、React Hook Form、Zod、i18next。

## 本地运行

```bash
npm install
npm run dev
```


## 可用流程

- 竞赛控制：起航倒计时、比赛状态切换、按最新数据重算的名次查看。
- 成绩管理：录入净用时和处罚秒数（更正进入待复核），复核确认后计入发布；发布记录保留全部历史版本，旧版本名次可回看。
- 抗议处理：提交抗议、进入复核、接受并处罚（秒数可调）或驳回，同时更新事件时间线。
- 数据使用 localStorage 持久化，刷新页面后继续保留。

## 发布账与多标签页协作

竞赛控制、成绩、抗议共用一份本地发布账（`regatta-ledger-v2`），规则如下：

- **发布门禁**：存在未结抗议（已提交/复核中）或待复核的更正、处罚时，正式成绩不能发布，成绩页会列出全部阻塞原因。
- **失效与重算**：抗议处罚或成绩更正影响名次后，生效中的发布版本立即失效；未结事项清理完毕时自动重算并发布新版本，否则保持失效待人工重发。旧版本（含名次快照）永久保留可查。
- **修订号并发控制**：每次提交携带本页看到的修订号，提交前在 Web Locks 锁内重读最新账本。修订号已变化时，后交的操作会重放到最新数据上合并保存（双方记录都保留）；操作本身不再适用（如抗议已被另一标签页结案）时拒绝并提示，绝不整树覆盖他人记录。头部实时显示当前修订号。
- **跨标签页同步**：其他标签页写入后通过 `storage` 事件即时同步到本页。
- **旧数据升级**：首次启动自动迁移 `regatta-control-v1`，原有比赛、成绩、抗议全部保留；旧数据含正式成绩时补建 v1 发布版本，旧键保留不删。
- **故障恢复**：每次写入后把可用版本镜像到备份键；主记录损坏时自动恢复上一可用版本，写入失败时不落盘、保留旧版本。损坏副本另存备查。
- **草稿找回**：成绩更正和抗议表单未完成时实时存入独立草稿键（不占用共享修订号），重新打开页面自动找回，提交成功后清除。
